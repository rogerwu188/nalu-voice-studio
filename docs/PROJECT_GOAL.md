# Nalu Voice Studio：完整项目目标

用户确认的目标：老人通过交谈，就能把故事或网上找到的小说，逐步创作为连续剧视频，并完成审核、发行的 macOS 应用。不只是语音聊天，也不只是生成几段视频。

## 1. 两种故事来源

- 自己讲故事：边讲、边理解、追问、整理，随时补充和修改，逐步形成故事和剧本。
- 网上内容：根据书名、网站、网址或查找要求实际搜索、读取、抓取可访问正文，整理章节并保存；访问失败明确提示，不假装读取成功。

## 2. 交互式剧本：当前第一优先级

- 执行找书、采用故事、修改人物、继续下一集等意图，不只是转录。
- 在交谈中维护背景、角色、情节和用户修改。
- 形成整部故事规划、分集大纲、每集剧本、分镜和台词。
- 支持确认、修改、退回，以及中断和重启后继续。

## 3. 逐集制作

- 确认剧本后实际生成角色、场景和镜头素材。
- 完成配音、字幕、音乐、音效与剪辑合成。
- 保持人物、剧情和跨集连续性。
- 展示进度和失败原因，支持恢复及局部重做。
- 保留原片和修订版，避免重复生成、重复扣费。
- 先使用现成自然 TTS；语音自然度和交互流畅度精修放在主流程跑通之后。

## 4. 审核与发行

- 播放检查每集成片，明确记录通过或未通过。
- 修订不合格镜头，不破坏已有版本。
- 审核通过后准备封面、标题、简介、分集内容和发行包。
- 获得对应账户、费用和发布授权后发行，记录结果，避免重复发布。

## 5. 可用的 macOS 产品

- 老人能找到、看懂、操作核心功能。
- 直接使用已保存密钥和 API 地址，不反复要求输入。
- 可靠保存项目、素材、剧本、制作任务和审核状态。
- 完成安装、升级、权限、异常恢复、可访问性测试及正式签名、公证。

## 6. 唯一完成标准

SOP-00 至 SOP-13 必须在同一个发布候选上具备实现、测试、CI、必要真实人工/E2E 验收和发行证据。以 PRODUCT_SOP.md 核验，以 GOAL_PROGRESS.json 接续工作。代码、单项测试、CI 或合成素材不等于完整产品验收。

优先级：两种来源 → 交互剧本 → 第一集真实成片 → 修订审核 → 后续集与发行。不得缩小目标到现有实现或以外围优化替代主线。
